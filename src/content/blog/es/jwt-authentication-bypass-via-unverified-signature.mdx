El JWT usa **RS256** (RSA-SHA256) para la firma, que es un algoritmo asimétrico. Sin embargo, la descripción del lab nos dice que el servidor **no verifica la firma** en absoluto. Esto significa que podemos simplemente modificar el payload sin preocuparnos por re-firmar el token. La firma será inválida, pero el servidor no la verificará.

Todo lo que necesitamos hacer es:
1. Decodificar el payload
2. Cambiar `"sub": "wiener"` a `"sub": "administrator"`
3. Re-codificar el payload
4. Reemplazar la parte del payload en el JWT original

Creemos un script de Python para forjar el JWT de administrador:

<CodeSnippet file="jwt-authentication-bypass-via-unverified-signature/09-python.py" />

> **Desglose del script**: \
> El script forja un JWT de administrador:
> 1. **Divide** el JWT original en sus tres partes (header, payload, firma)
> 2. **Decodifica** el payload base64url para obtener los claims JSON
> 3. **Altera** el claim `sub` de `"wiener"` a `"administrator"`
> 4. **Re-codifica** el payload modificado de vuelta a base64url
> 5. **Reensambla** el JWT con el header y la firma originales. El servidor no verificará la firma de todos modos.

## Estrategias de Mitigación

1. **Siempre verificar las firmas JWT**: Usa el método `verify()` de tu librería, nunca solo `decode()`. Este es el requisito de seguridad JWT más fundamental
2. **Usar librerías JWT bien mantenidas**: Confía en librerías probadas en batalla que manejen la verificación por defecto en lugar de implementar el manejo de JWT desde cero
3. **Aplicar validación de algoritmo**: Especifica explícitamente qué algoritmos acepta el servidor y rechaza tokens que usen algoritmos inesperados
4. **Validar todos los claims del JWT**: Siempre verifica el emisor (`iss`), expiración (`exp`) y otros claims del lado del servidor
5. **Implementar defensa en profundidad**: No dependas únicamente de la validación JWT. Añade validaciones de sesión del lado del servidor y controles de autorización como capas adicionales

## Referencias

**Claims\*** son declaraciones sobre una entidad (típicamente el usuario) y datos adicionales, como identidad (`sub`), emisor (`iss`), tiempo de expiración (`exp`) y otros metadatos. [Más información sobre JWT claims](https://datatracker.ietf.org/doc/html/rfc7519#section-4)
